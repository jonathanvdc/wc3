
## M2 record derives

Import `wc3::model::formats::m2` and derive `m2::Read`, `m2::Write`, and
`m2::RecordLayout` for structs whose fields have composable M2 codecs. Named,
tuple, unit, and generic structs are supported. Read and write field bounds are
independent: reading a record does not require its fields to support writing.
The write derive additionally requires `RecordLayout` so it can reserve the
complete metadata region before allocating payloads.

```rust
use wc3::model::formats::m2;
use m2::codec::{Decoder, Encoder};
use m2::{Read as _, Write as _};

#[derive(m2::Read, m2::Write, m2::RecordLayout)]
struct Example<'data> {
    values: m2::ZeroVec<'data, u16>,
    identifier: u32,
}

let value = Example {
    values: m2::ZeroVec::alloc_from_slice(&[10, 20]),
    identifier: 7,
};
let mut encoder = Encoder::new(264, Default::default());
value.write(&mut encoder)?;
let bytes = encoder.finish();
let decoded = Example::read(&mut Decoder::new(&bytes, 264, Default::default()))?;
assert_eq!(decoded.identifier, 7);
assert_eq!(decoded.values.get(1), Some(20));
# Ok::<(), Box<dyn std::error::Error>>(())
```

Fields appear in declaration order. Scalars and fixed arrays occupy inline
metadata. A `ZeroVec<T>` field occupies an eight-byte count/offset descriptor;
its fixed-width values borrow the containing address space. A `Vec<T>` field
also occupies a descriptor, addressing an array of inline record headers and
any nested payloads. `RecordLayout` describes only the inline width, and the
writer reserves that entire width before allocating out-of-line data.

Version-selected associated field types use the same field codecs. Implement
specialized codecs for runtime-discriminated payloads, external animation
leaves, and file framing rather than encoding those rules as derive attributes.
The derives operate within an address space; whole-file model entry points are
`Model::decode_m2` and `Model::encode_m2`.

### Validation and animation traversal

Derive `m2::Validate` and `m2::VisitArrays` for ordinary record structs and enums.
Named, tuple, and unit forms are supported, including lifetime, type, and const
parameters. Each operation delegates to its fields in declaration order; an
enum visits only the active variant. Validation returns the first field error,
and traversal stops at the first visitor error while preserving earlier
mutations. The derives add field-specific trait bounds without requiring
ownership, codec, `Clone`, or `Default` implementations.

```rust
use wc3::model::formats::m2;
use m2::Validate as _;

#[derive(m2::Validate, m2::VisitArrays)]
struct Metadata<T, const N: usize> {
    identifier: u32,
    records: [T; N],
}

let metadata = Metadata { identifier: 7, records: [1u16, 2] };
metadata.validate()?;
# Ok::<(), m2::ReadError>(())
```

A containing record delegates animation traversal to its fields. Native track
implementations provide the sequence and global-loop context when visiting
leaves; the derive does not infer that context from adjacent scalar fields.
Use a handwritten `Validate` implementation for relationships between fields,
such as timestamp/value cardinality or start/end ordering. Contextual traversal
likewise remains handwritten at the leaf or record that owns that context.

### Scalar enums and flags

Use a scalar enum for a field whose wire code selects a named choice. The
`m2::Value` derive supplies `from_raw`, `raw`, and `From` conversions;
codec and layout derives use the declared integer width independently of that
derive. Every enum requires exactly one `Unknown` payload with the same wire
type, so unrecognized codes round-trip without being interpreted as a known choice.

```rust
use wc3::model::formats::m2;

#[derive(Clone, Copy, Debug, PartialEq, Eq,
         m2::Value, m2::Read, m2::Write, m2::RecordLayout)]
#[m2(value = u16)]
enum Mode {
    #[m2(value = 0)]
    Disabled,
    #[m2(value = 1)]
    Enabled,
    #[m2(unknown)]
    Unknown(u16),
}

assert_eq!(Mode::from_raw(1), Mode::Enabled);
assert_eq!(Mode::from_raw(65535), Mode::Unknown(65535));
assert_eq!(Mode::Unknown(65535).raw(), 65535);
```

Known variants must be unit variants with distinct integer literal codes.
Signed wire types support negative codes. Revision numbers, indices, counts,
and offsets remain numerical fields. Use `bitfield!` tuple structs for flag
words, with named getters and setters for established bits and a whole-word
`bits` accessor for preserving unrecognized bits. Their codec derives delegate
to the underlying integer field; they do not reinterpret the flags as enum choices.
