
## M3 record derives

Import `wc3::model::formats::m3` to define fixed inline records for indexed M3 sections.
Derive `m3::Read`, `m3::Write`, and `m3::RecordLayout` together when each field
already implements the corresponding codec trait. Named, tuple, unit, and
generic structs are supported. Fields retain their declaration order; reading
and writing impose independent field bounds.

```rust
use wc3::model::formats::m3::{self, Md33, Md34, Ref};
use m3::codec::{Decoder, Encoder};

#[derive(m3::Read, m3::Write, m3::RecordLayout)]
struct Example {
    identifier: u32,
    values: Ref,
}

let record = Example { identifier: 7, values: Ref::from_section(2, 3) };
let mut output = Encoder::<Md34>::new();
output.write(&record)?;
let bytes = output.finish();
let decoded: Example = Decoder::<Md34>::new(&bytes).read()?;
assert_eq!(decoded.identifier, 7);
assert_eq!(<Example as m3::RecordLayout<Md33>>::size(), 12);
assert_eq!(<Example as m3::RecordLayout<Md34>>::size(), 16);
# Ok::<(), Box<dyn std::error::Error>>(())
```

The generated implementations are generic over the envelope. `Md33` encodes
eight-byte count/index references, while `Md34` adds a four-byte flag word.
A nonzero reference flag cannot be written under `Md33`. The envelope controls
reference width independently of each section's record revision. Implement
`m3::Record` explicitly to associate a concrete record with its section tag and
revision; the derives do not infer either identity from a Rust type name.

A `Ref<T>` field names its target section family through `m3::Target`. It stores
a count and a stable section index rather than embedding the target records.
Use actual record types for exact-revision resolution or family markers when
the field can reference independently revised records. `Ref` without a target
parameter retains a reference whose expected tag is unknown. These codecs
encode one record; the indexed `Container` API owns section resolution and file
placement.

Derive `m3::Validate` and `m3::VisitReferences` for compositional field checks
and reference traversal. Both support structs and enum payloads and visit
fields in declaration order. Their bounds are independent of the envelope and
codec traits. Validation stops at the first field error; reference traversal
passes each reference, including empty references, to a `ReferenceVisitor`
without resolving its target. Use handwritten validation for relationships
between fields. Runtime-discriminated representations with variable payloads require their own
reader and writer.

Select native layout differences with
field types and record revisions, and use `RecordLayout` only for fixed inline
widths. A borrowed `Array<'data, T, E>` decodes fixed records lazily from section
bytes; its storage is distinct from the inline references that connect sections.

### Scalar enums and flags

Use a scalar enum for a field whose wire code selects a named choice. The
`m3::Value` derive supplies `from_raw`, `raw`, and `From` conversions;
codec and layout derives use the declared integer width independently of that
derive. Every enum requires exactly one `Unknown` payload with the same wire
type, so unrecognized codes round-trip without being interpreted as a known choice.

```rust
use wc3::model::formats::m3;

#[derive(Clone, Copy, Debug, PartialEq, Eq,
         m3::Value, m3::Read, m3::Write, m3::RecordLayout)]
#[m3(value = u16)]
enum Mode {
    #[m3(value = 0)]
    Disabled,
    #[m3(value = 1)]
    Enabled,
    #[m3(unknown)]
    Unknown(u16),
}

assert_eq!(Mode::from_raw(1), Mode::Enabled);
assert_eq!(Mode::from_raw(65535), Mode::Unknown(65535));
assert_eq!(Mode::Unknown(65535).raw(), 65535);
```

Known variants must be unit variants with distinct integer literal codes.
Signed wire types support negative codes. Revision numbers, indices, counts,
and offsets remain numerical fields. Use `bitfield!` tuple structs for flag
words, with named getters and setters for established bits and a whole-word
`bits` accessor for preserving unrecognized bits. Their codec derives delegate
to the underlying integer field; they do not reinterpret the flags as enum choices.
