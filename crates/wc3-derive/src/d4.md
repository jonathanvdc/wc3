
# Diablo IV native records

Import the D4 derives through `wc3::model::diablo::d4`. Maintained Rust declarations
describe each record's wire-order fields and descriptor encodings. The derives
compose the checked decoder and relocating writer; document layout markers
continue to select the exact resource format hash.

```rust
use wc3::model::{common::Ownership, diablo::d4};
use d4::{Read as _, RecordLayout as _, Write as _};
use d4::codec::{Decoder, Encoder, Space};

#[derive(Clone, Debug, PartialEq, Ownership,
         d4::RecordLayout, d4::Read, d4::Write)]
struct Record {
    #[d4(value)]
    resource: i32,
    #[d4(value)]
    flags: u32,
}

let source = Record { resource: 12, flags: 3 };
assert_eq!(Record::SIZE, 8);
let mut encoder = Encoder::new(Record::SIZE);
source.write(&mut encoder, 0, Space::Main)?;
let (body, payload) = encoder.finish();
assert!(payload.is_empty());
let decoded = Record::read(&Decoder::new(&body, None), 0)?;
assert_eq!(decoded, source);
# Ok::<(), Box<dyn std::error::Error>>(())
```

Fields encode consecutively in declaration order. `RecordLayout::SIZE` is computed
from their encoded widths. Each field begins after the encoded width of the
preceding field; there is no implicit alignment or padding. Represent reserved
bytes with explicit fields, including trailing padding. An unqualified field is
an inline record implementing the corresponding
D4 trait. The additional encodings select how the field occupies native storage:

| Field attribute | Rust storage | Fixed width |
| --- | --- | --- |
| `value` | A scalar or scalar array implementing `common::AsULE` | Encoded ULE width |
| `array` | `ZeroVec<'data, T>` for encoded leaves, or `Vec<T>` for records | 16-byte descriptor |
| `inline_array` | `[T; N]` of inline records | `N * T::SIZE` |
| `bytes` | `Cow<'data, [u8]>` | 16-byte descriptor |
| `polymorphic = HASH` | `Vec<d4::records::Polymorphic<'data>>` | 24-byte descriptor |

`array` and `polymorphic` can additionally specify `external`, selecting the
separately supplied payload body. The writer allocates referenced data in that
address space and rebuilds the descriptor. The polymorphic hash identifies the
declared base family; concrete dispatch still checks the supported native types.

`Read` borrows encoded leaves and resolves nested metadata. `Write` requires
previously reserved fixed storage, then relocates referenced data. Both check the
complete fixed record range before computing field addresses. Keep cross-field
invariants in handwritten trait implementations where a declaration needs more
than this field composition.

`RecordLayout` sums the encoded field widths with checked arithmetic. Empty inline
arrays consume zero bytes, and generic records derive their width from the
instantiated field types. Changes to fields or reserved bytes change the inferred
size; keep documented native widths in layout tests when defining a file format.
Concrete layouts are checked during compilation; type- or const-generic layouts
are checked when their `SIZE` is evaluated.

`Read` and `Write` check that the computed width agrees with `RecordLayout`,
including when that trait is implemented by hand.

A handwritten size must agree with the encoded field widths:

```compile_fail
use wc3::model::diablo::d4;
use d4::Read as _;
use d4::codec::Decoder;

#[derive(d4::Read)]
struct Disagreement {
    #[d4(value)]
    value: u32,
}
impl d4::RecordLayout for Disagreement {
    const SIZE: usize = 8;
}
let bytes = [0; 8];
let _ = Disagreement::read(&Decoder::new(&bytes, None), 0);
```

Encoded width arithmetic must fit in `usize`:

```compile_fail
use wc3::model::diablo::d4;

struct Huge;
impl d4::RecordLayout for Huge {
    const SIZE: usize = usize::MAX;
}
#[derive(d4::RecordLayout)]
struct Overflow {
    first: Huge,
    #[d4(value)]
    last: u8,
}
```

An empty scalar array uses `inline_array`. The `value` encoding requires a
nonzero ULE width, so this declaration is rejected:

```compile_fail
use wc3::model::diablo::d4;

#[derive(d4::RecordLayout)]
struct EmptyValue {
    #[d4(value)]
    values: [u8; 0],
}
```

Descriptor-backed arrays also require nonzero element widths in both reading
and writing.

Ownership uses the existing `common::Ownership` derive independently of the
codec derives. Its buffer lifetime is named `'data`, as in the other model
formats. `as_borrowed` creates a view over owned or borrowed leaves, and
`into_owned` detaches their storage. D4 enum dispatch and specialized native
invariants retain handwritten codecs.
